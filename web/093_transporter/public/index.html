What this place is

A left-luggage office that cannot open the bags

Every locker here belongs to one Grin address. Anyone can post something into yours — that is how you get paid. Nobody but you can open it, because the door is unlocked by the same key that owns the address, and that key never leaves your wallet.

What arrives is already sealed before it gets here. This depot stores a package it has no way to open, hands it over to whoever proves they own the locker, and destroys the wrapper afterwards.

The depot has no wallet and no Grin address of its own. It cannot receive, hold, or forward a single coin, and nobody ever pays it. A payment is addressed to the recipient's own address, exactly as it would be if it went straight over Tor — the only difference is that the sealed message waits here instead of arriving the instant it is sent.

If nobody collects, the package is destroyed after {{TTL_DAYS}} and the sender gets their funds back untouched.

Read this bit twice

We cannot read your package. We do know that one moved.

This depot records which address posted to which, and when — it has to, to deliver. It never sees amounts, names or contents. If that metadata matters to you, hand the slatepack over yourself, or run your own depot. The software to run one is the same software running this page.
The round trip

Four moves, and neither of you has to be awake for the other

When that actually matters
Case one

Payday lands while your rig is switched off

A pool pays out on its own schedule. If your wallet is not listening at that exact minute, a direct payment simply fails and you go into a retry queue — for days, sometimes for nothing. A locker does not care when you show up.

Case two

Tor cannot get out of the country you are in

Where Tor is blocked outright and even bridges — obfs4, Snowflake — will not hold a circuit, a direct payment has nowhere to go. Collecting from a depot is an ordinary HTTPS request to an ordinary web server, so it travels wherever normal web traffic travels.

The trade is real: reached over plain HTTPS, the depot sees your IP address. Use its .onion where you can reach one — or run the depot yourself, and it is your own server doing the seeing.
Case three

You are twelve hours apart and never both awake

Two people, no shared chat window, opposite timezones. The alternative is emailing blocks of slatepack text back and forth and hoping neither of you pastes the wrong one. Each of you does your half whenever it suits.

Worth being clear about what this is not: it is not a way around Tor being down on your own machine, and it is not a privacy upgrade. Case two works because the depot speaks plain HTTPS — the same reason it can be blocked, logged, or watched like any other website. If both wallets are online and Tor is working, send directly; it is simpler and it leaves nothing behind on anyone's server.

Key holders

Which wallets can open a locker

Being honest about this up front saves you an afternoon: most Grin wallets cannot use a depot at all. grin-wallet, Grim and Goblin speak Tor, an HTTP listener and hand-carried slatepacks — none of them has a relay client. There is nothing to configure in them, and nothing you can paste into them that will work.

One wallet has it built in: Fidelius, the Grin Node Toolkit's own self-hosted web wallet. Everything else needs the toolkit's command-line poll agent bolted onto a local grin-wallet.

Fidelius · toolkit script 051

The only wallet with depot support built in — no CLI, no cron, nothing to bolt on. Paste this station's URL once under Settings → Grin Transporter (one slot per network), and a Send via Transporter method appears beside Tor and Slatepack, with a Transporter Inbox that collects, finishes and replies to what is waiting. It drives the wallet's Owner API in-process, so the passphrase never touches disk.

Fits the lock

grin-wallet · plus the 093 poll agent

The reference wallet has no relay client of its own, but the toolkit ships agent.js, which drives its Owner API from outside. A plain Node script — no daemon, a cron entry is enough. This is the route for a wallet you already run headless next to a node.

With the agent

grin-wallet on its own, Grim, Goblin, everything else

Tor, an HTTP listener and manual slatepacks only. A depot is not a listener and not a slatepack you can paste — it is a queue that has to be polled and authenticated against, so support has to be written into the wallet. None of these has it.

No relay client

Both ends need one. A depot is not something you can pay into from an unaware wallet: the sender deposits and the recipient collects, so payer and payee both need Fidelius or the agent, and both need to be pointed at a depot on {{NETWORK_LOWER}}. If your counterparty runs neither, send over Tor instead. 

# the address to hand out — this is your locker
$ agent.js address

# collect anything waiting, add your half, post the reply back
$ agent.js poll

# deposit a payment into someone else's locker
$ agent.js send <recipient_address> <amount_grin>

# what's in flight, and what the depot is holding for you
$ agent.js status

# abandon a transaction you started
$ agent.js cancel <tx_slate_id>

Install either side with 093_grin_transporter.sh in the Grin Node Toolkit — option 7 wires the agent to a local wallet, option 8 runs it and installs the cron schedule that polls for you; Fidelius is installed separately by 051_grin_fidelius.sh and just needs the URL. If you would rather not trust someone else's depot with your delivery metadata, the same script installs the server side. Running your own is the intended configuration, not the advanced one.

Where the idea came from

An old idea, rebuilt on modern keys

This is not a new invention and does not pretend to be. Grin had a relay once; it was removed, and the gap it left is the gap this fills.

2018 — 2019

grinbox (vault713) gave Grin its first relay: your address was your mailbox, encrypted messages waited in a queue, and you proved ownership to collect. wallet713 was the wallet that spoke it.

Then

Grin core never adopted it. grinbox addressing was dropped from the wallet, and the relay went with it. MWC kept the concept alive in mwcmqs, which still runs today as a public federated service.

Borrowed

The shape: a queue keyed by address, challenge-response instead of accounts, plain HTTP rather than email. That design was right in 2018 and it is still right.

Not borrowed

The cryptography. grinbox and MQS use the old secp256k1 addressing. This depot never touches any of that — it carries the ed25519 Slatepack your wallet already produces, and implements no cryptography of its own. Every seal is made and broken inside a wallet, never here. It is a fresh build that studied the old one, not a fork of it.

And

Those relays were central and public by default. This one is meant to be yours — one operator, one depot, run wherever you already run a node.
