Wallet identity

The pool pins its wallet's address (slatepack index 0, derived from the seed). If a different wallet ever answers the owner API, payouts auto-freeze. Before switching wallets, run the wizard so the guard adopts the new wallet instead of tripping.

Switch wallet
  1. Freeze payouts — stop the scheduler before touching the wallet.
  2. Let in-flight payouts settle — checking…. Don't swap the wallet while sends are mid-flight.
  3. Switch the wallet on the server — restore the seed / repoint the listener, then wait for a full rescan so the balance is accurate. (Manual step on the VPS.)
  4. Verify the new wallet
    not checked yet
  5. Adopt new wallet + resume — pins the new wallet as the pool identity, then resumes payouts.

Abandoned balances

Balances of addresses idle past the dormancy window are swept and redistributed to active miners (never operator revenue). Configure the window in Settings → Payout. Disposition is FINAL and honours the payout freeze. All amounts GRIN (ツ), times UTC.

Pay a below-minimum miner

For a miner below the minimum who emails to withdraw. First verify they own the address (type the mining IP or rig password they gave you → match/no-match, nothing is revealed). Then either:
• Send Tor payout now — the pool sends it over Tor through the normal locked flow and records it automatically (they need their wallet listener online for a moment); or
• Record an out-of-band send — if you already sent the coins yourself (slatepack / wallet CLI), log it here so coverage stays correct and the wallet-send audit matches your send.
