    How regions work — adding a gateway, start to finish (Model C)

    A gateway is a small extra server in another location. It runs only HAProxy + WireGuard — no grin node, no wallet, no database. Miners in that location connect to the gateway, and it forwards their stratum traffic through an encrypted tunnel to this pool box. This box stays the single brain: all shares, blocks and payouts are still handled here.

    Every region needs one region key — a short airport-style code like nyc, sgn, ams. Five steps, and only two of them are on this page:

    1. STEP 1 — Enable multi-region (once per pool, on this page).
      Your pool needs its own WireGuard tunnel before any gateway can peer with it. If the banner at the top of this page offers Enable multi-region, click it now.
      Already done for you if the banner says the tunnel is up. Skipping this is the single most common way the pairing below fails.
    2. STEP 2 — Install on the gateway box (SSH there, not here).
      On the gateway server, run 07_grin_mining_public_pool.sh → 2) Regional gateway → 1) Install. It prints that box's WireGuard public key — copy it and stop there; the next step is back here.
      Result: one 44-character key ending in =.
    3. STEP 3 — Create the region + pair the key (on this page).
      Click ➕ New region: fill region key, city, country (and, optionally, its map position), the stratum hostname miners will use (e.g. sgn.grinium.com), and paste the gateway's public key into the Gateway WireGuard public key field. Save.
      Result: the page shows a one-line GRINGW1|… pairing string with a copy button. The tunnel listener is live immediately — no service restart.
    4. STEP 4 — Paste the string on the gateway box, and point DNS at it.
      Back on the gateway: 2) Configure → paste the GRINGW1|… line (fills every field) → 3) Bring up tunnel → 4) Start.
      Then create the DNS A-record for the hostname you typed in step 3, pointing at the gateway box's public IP — not this pool box's.
      Both halves matter: the tunnel carries the shares, the A-record is how a rig finds the gateway at all.
    5. STEP 5 — Watch the row (this page).
      The Tunnel chip goes 🔒 green within ~30s of step 4. The Port check column only goes ✓ once DNS resolves and the gateway's stratum port is open there. Mining activity flips to ● Active once a rig actually connects.
      Green tunnel + ✗ port is almost always DNS still propagating, or a firewall on the gateway box — not a pairing fault.

    Single-box pool? You don't need gateways — the pool auto-registers its own region and miners just use that one host. Leave the key field empty to save a metadata-only region card (no tunnel).
    Lost the pairing string? Use the row's 🔑 button — it re-derives the exact same line.
    Replacing a gateway box? Pair the NEW box's key under the SAME region key — the region keeps its tunnel IP and port, so nothing else changes.
    This page ≠ "Public Stratum Host" in Pool Info — that field is only the cosmetic fallback host, not a region/gateway registration.
    SSH fallback: Script 07 → W) Multi-region does the same pairing from the terminal — both paths share one helper, so they never drift.

    The Port :NNNN column (named after your public miner port) is an active wire test: on every refresh the pool box TCP-dials the region's public stratum host:port — the exact connection a miner's rig makes; the badge repeats the exact port it dialed. ✓ open = the gateway's forwarder answered (with round-trip ms); ✗ unreachable = refused / timed out / DNS failed. This is the miner port only — it is not the internal Region port, the WireGuard port, or the grin node's stratum port. Mining activity is the passive signal — no port is dialed for it: recent shares (miners actually mining the region) plus, when available, the WireGuard tunnel's last handshake; Active <3 min, Stalling 3–10 min, Silent >10 min. Port ✓ with No signal simply means the gateway is up but no miner is on it yet. A hidden tag on a region name means you've unchecked "Visible on site" in its edit form — that region is hidden from the public connect grid.

        What goes in each field? (click for a quick guide)
        
    
          
    Region key
    
          
    Short permanent identifier for this location — lowercase letters/digits/dashes, 2–12 chars.
              Suggestion: a 3-letter airport (IATA) code — nyc, lax,
              ams, yyz, han — or a 2-letter country code (us,
              nl, vn) when a country has one region. Shares get tagged with it, so it
              can't be renamed later; it also becomes the WireGuard peer tag when you pair a gateway key below.
    
          
    Label / City
    
          
    Human-friendly name shown on the public connect card (e.g. New York). Cosmetic — doesn't affect routing.
    
          
    Country & country code
    
          
    Group regions by country on the dashboard (two US regions appear under one heading). The ISO-2 code
              (US, NL) draws the flag emoji. Leave the code blank for no flag.
    
          
    Map position (lat / lng) — optional
    
          
    Where the public network map pins this gateway, in decimal degrees (Los Angeles 34.05 /
              -118.24, New York 40.71 / -74.01). Leave both blank and the marker
              sits on the country's centre — fine for one region per country, but two US gateways then land 140 km
              apart in Kansas, which looks like a bug. This is the gateway box, a public server whose hostname
              is already on the connect grid — it says nothing about any miner. Miners are always drawn as a shaded
              country, never a point.
    
          
    Stratum host
    
          
    The hostname miners point their rigs at for this region (e.g. nyc.grinium.com). Create a DNS
              A-record for it that resolves to the gateway box's public IP. Enter the host only — the
              shared stratum port is appended automatically.
    
          
    Gateway WireGuard public key — optional
    
          
    The 44-character key (ends =) that the gateway box's 1) Install printed. Paste it and
              Save does the whole pairing: the wg peer is added, a tunnel IP + internal region port are assigned, the
              region's stratum listener binds immediately (no restart), and you get the GRINGW1|… string to
              paste back on the gateway box. Leave empty for a metadata-only card (single-box region, or a gateway paired
              earlier via SSH). Re-pairing the SAME key changes nothing; pairing a NEW key under the same region swaps the
              gateway box while keeping its tunnel IP + port.
    
          
    Visible on site
    
          
    A show/hide switch, nothing more — when on, the card appears on the public connect grid (as “No signal”
              until the gateway box has its pairing string applied and starts forwarding — STEP 3). Turn off to hide a
              region without deleting it. It does not check whether the gateway is running; that's the
              Port, Tunnel and Mining activity columns.
