# Toolkit findings from writing the grinnode.org manual

> **Covers code as of:** 2026-09-23 (each row was read against the code on the date of its session, 2026-09-19 → 2026-09-23)
> **Last verified:** never systematically verified — every row is a code read, not a VPS run, unless the row says otherwise
> **Product code last changed:** n/a — spans scripts 01–09 and their libs; re-read the named file before acting on a row

The public manual at [grinnode.org/docs/](https://grinnode.org/docs/) (sources in the `Grin-Landing-Pages` repo,
`docs-src/grinnode-org/`) was written in eleven sessions, M0–M10, with one rule: **the code wins** — every key, path,
port and claim was taken from the scripts, not from the README or CLAUDE.md. Wherever the two disagreed, the manual
says what the code does and the disagreement was logged. This file is that log, kept so the fixes can be made here.
The manual pages already warn readers about every item that affects them, so fixing one here also means editing the
matching manual page (search the landing repo for the script number).

**Kinds of row:** most are *stale text* (README, CLAUDE.md, a menu hint or a `docs/generated/` doc that no longer
matches the code); some are *probable bugs* (code read only — confirm on a VPS before editing, per CLAUDE.md
"Confirm root cause before editing"); a few are *observations* (design choices worth a second look). Rows marked
"Memory corrected" or "fixed" need no further action.
